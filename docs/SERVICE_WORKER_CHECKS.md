# Ручная проверка service worker

ADR 0006 предупреждает об этом прямо: **ошибки в worker проявляются на втором визите, не
на первом.** Любая проверка, сделанная одной загрузкой, ничего не доказывает, а CI не
доказывает вообще ничего — `jsdom` не даёт ни `ServiceWorkerGlobalScope`, ни `caches`, ни
переключателя сети.

Автотестами закрыто только то, что честно закрывается: генерация списка прекеша, версия
кеша, решение о маршрутизации запроса и удаление чужих кешей
(`tools/service-worker/build-sw.test.ts`, 19 тестов). Всё остальное — руками, по этому
списку, **при каждом изменении worker или списка прекеша**.

Проверять надо на собранном экспорте, а не в `next dev`: в разработке worker не
генерируется вовсе.

```bash
npm run build && npx serve out    # или любой статический сервер из корня out/
```

---

## 1. Первый визит — worker ставится и не спрашивает ничего

- [ ] Открыть приложение. DevTools → Application → Service Workers: worker
      **activated and is running**.
- [ ] Cache Storage: есть `worauf-static-<версия>`, в нём порядка 70 записей
      (`/_next/static/**` + три оболочки `/`, `/en/`, `/ru/`).
- [ ] **Плашки «Готова новая версия» нет.** Первый worker заменять нечего — если плашка
      появилась, сломано условие «только замена, не первая установка».
- [ ] В подвале справочника виден хеш данных (`данные a1b2c3…`) — он же в экспорте прогресса.

## 2. Офлайн — то, что обещано, и ровно оно

- [ ] Network → Offline, перезагрузить страницу: приложение открывается, поиск работает,
      любое слово из посещённых открывается.
- [ ] Офлайн перейти на слово, **которое не открывали** при живой сети: страница не
      открывается — так и задумано (ADR 0006, «Чего решение сознательно не даёт»).
      RSC-пейлоад маршрута не прекеширован и прекеширован быть не может: их 4884 на ~100 МБ.
- [ ] Онлайн открыть несколько слов, снова офлайн — теперь они открываются из
      `worauf-documents-<версия>`.
- [ ] Тренажёр офлайн проходит сессию целиком и сохраняет прогресс (датасет уже в чанке,
      IndexedDB сети не требует).

## 3. Второй визит и обновление — главное, что здесь можно сломать

Именно этот раздел не проверяется ничем, кроме рук.

- [ ] Изменить что-нибудь в данных или в коде, `npm run build` заново, обновить страницу
      **один раз**.
- [ ] Появилась плашка «Готова новая версия» — и **страница не перезагрузилась сама**.
      Молчаливое самообновление в приложении, которое учит падежам, — дефект, а не удобство.
- [ ] DevTools → Service Workers: новый worker в состоянии **waiting**, старый всё ещё
      контролирует страницу.
- [ ] Нажать «Обновить»: страница перезагружается один раз, новый worker становится
      активным, старые кеши (`…-<прежняя версия>`) удалены.
- [ ] Проверить, что **не случилось цикла перезагрузок** — флаг «мы сами попросили»
      в `useAppUpdate` существует именно ради этого.
- [ ] Открыть приложение во второй вкладке, в первой нажать «Обновить»: вторая вкладка не
      должна перезагрузиться неожиданно для читателя (её `controllerchange` придёт, но без
      согласия — без перезагрузки).

## 4. Заголовки на выкладке

- [ ] После `npm run build` файл `out/_headers` существует и содержит правило для `/sw.js`.
- [ ] На выложенном стенде: `curl -sI https://<хост>/sw.js | grep -i cache-control` →
      `no-cache, no-store, must-revalidate`. Без этого браузер может сутки отдавать старый
      worker, и поток обновления перестанет работать именно тогда, когда он нужнее всего.
- [ ] `curl -sI https://<хост>/_next/static/<любой чанк>` → `immutable`.

## 5. Установка

- [ ] DevTools → Application → Manifest: без ошибок, иконка отображается.
- [ ] Установить на домашний экран, открыть из ярлыка: приложение открывается на `/en/`
      без промежуточного редиректа.
- [ ] Открыть установленное приложение в самолётном режиме: работает (см. раздел 2).

## Если worker надо снять

Откатить его **выкладкой нового worker, который снимает сам себя**, а не выкладкой без
worker: установленный worker живёт у читателя, пока его не разгрегистрируют, и «версия без
worker» его не тронет. ADR 0006 называет это тяжело обратимым решением — так и есть.
Минимальный самоснимающийся worker:

```js
self.addEventListener('install', () => self.skipWaiting());
self.addEventListener('activate', async () => {
  await Promise.all((await caches.keys()).filter((n) => n.startsWith('worauf-')).map((n) => caches.delete(n)));
  await self.registration.unregister();
  for (const client of await self.clients.matchAll()) client.navigate(client.url);
});
```
