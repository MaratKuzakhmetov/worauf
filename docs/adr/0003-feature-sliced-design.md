# ADR 0003 — Feature-Sliced Design

**Статус:** Принято, 2026-09-02.

---

## Контекст

Просьба владельца проекта. В существующих проектах (`personal-website`, `translate-app`)
раскладка классическая — `components / hooks / utils`, — так что это новая для репозитория
конвенция, а не перенос существующей.

Оговорка, которую стоит зафиксировать честно: для того объёма кода, что есть в фазе 0,
FSD избыточен. Он начинает окупаться к фазе 4, когда рядом окажутся справочник, тренажёр
и повторения, каждый со своим состоянием, и когда встанет вопрос, кому позволено импортировать
логику отбора отвлекающих вариантов. Заводить методологию до этого момента дешевле, чем
переезжать на неё после.

---

## Решение

Feature-Sliced Design по официальному руководству для Next.js App Router.

**Маршруты Next остаются в корневом `app/`, весь FSD живёт в `src/`.**
Слои `app` и `pages` переименованы в `_app` и `_pages` — иначе `src/app` конфликтует
с директорией маршрутов Next, которая ищется и в корне, и в `src/`.

```
app/                      маршруты Next — только реэкспорт
  [lang]/
    layout.tsx            export { LocaleLayout as default, … } from '@/_app'
    page.tsx              рендерит HomePage из @/_pages/home

src/
  _app/                   инициализация: корневой layout, шрифты, глобальные стили и токены
  _pages/home/            страница как композиция виджетов
  widgets/app-header/     составной блок интерфейса
  features/
    theme-toggle/         действие пользователя: смена темы (+ boot-скрипт)
    locale-switch/        действие пользователя: смена языка
  shared/
    i18n/                 локали и таблица строк
    lib/slug/             свёртывание слагов (ADR 0002)
    lib/urls/             абсолютные адреса и basePath
    ui/wordmark/          логотип
```

Правило импорта: слой видит только слои **строго ниже** себя. Внутри слайса — сегменты
`ui / model / api / lib / config`, наружу торчит только `index.ts`.

---

## Чего в структуре намеренно нет

**`entities` пустует.** Бизнес-сущностей в фазе 0 ещё не существует; заводить пустой слой
ради полноты схемы — ровно тот карго-культ, за который FSD и ругают. Слой появится в фазе 1
вместе с `entities/rektion` и `entities/preposition`, когда появятся сами данные.

**`processes` не используется** — слой объявлен устаревшим в самой методологии.

---

## Последствия

**Становится легче.** Границы стали проверяемыми утверждениями, а не пожеланиями:
`features/theme-toggle` физически не может импортировать `widgets/app-header`.
Маршрутный файл теперь состоит из одной строки, поэтому логика страницы не прирастает
к особенностям роутера — если Next когда-нибудь поменяет соглашения (а он это делает),
переписывать придётся `app/`, а не `src/`.

**Становится труднее.** Файлов заметно больше: у каждого слайса свой `index.ts`, у каждого
компонента свой сегмент `ui`. Для одной страницы это выглядит избыточно, и какое-то время
будет.

**Правило импортов пока держится на ревью.** Автоматической проверки нет: `steiger` или
`eslint-plugin-boundaries` её дают, но это новая зависимость, а по `CLAUDE.md` установка
требует явного согласия. Вернуться к вопросу стоит, когда появится третий слайс на слое.
