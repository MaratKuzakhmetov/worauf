# Модель данных — worauf

Статус: **черновик, ожидает подтверждения**. Это центральный документ проекта: интерфейс, тренажёр и импорт данных выводятся отсюда, а не наоборот.

---

## 1. Главное решение

**Центральная сущность — не слово и не предлог, а связка (Rektion).**

Это следует из трёх свойств немецкого управления, каждое из которых ломает наивную схему «таблица глаголов ↔ таблица предлогов»:

1. **Одно слово даёт несколько связок с разными значениями.**
   `sich freuen auf` (предвкушать) ≠ `sich freuen über` (радоваться случившемуся).
   `bestehen auf` / `aus` / `in` — три разных глагола по смыслу.
   `denken an` (держать в мыслях) ≠ `denken über` (иметь мнение).
   Значение принадлежит паре «слово + предлог», а не слову.

2. **Падеж принадлежит связке, а не предлогу.**
   `auf` — Wechselpräposition, но в `warten auf` всегда Akkusativ, а в `bestehen auf` всегда Dativ.
   Правило «wohin → Akk, wo → Dat» здесь не работает вообще: у предложного объекта нет
   пространственного значения, падеж лексикализован и его надо просто знать.
   Это и есть главная причина существования приложения.

3. **Управление есть не только у глаголов.**
   Прилагательные: `stolz auf + Akk`, `zufrieden mit + Dat`.
   Существительные: `die Angst vor + Dat`, `das Recht auf + Akk`.
   Это та же сущность с другим значением поля `pos`, а не отдельная подсистема.

Следствие: `pos` — атрибут слова, `case` — атрибут связки, `translation` — атрибут связки.

## 2. Формат авторской записи

Данные пишутся руками. Значит, формат выбирается не по удобству чтения программой,
а по тому, **какие ошибки он делает невозможными**.

### Наблюдённая ошибка, которую формат обязан исключить

В прототипе массив был сгруппирован по предлогам:

```
/* ---- an + Dativ ---- */   ... denken an ...
/* ---- über + Akk ---- */   ... (denken über — пропущено)
```

Когда дописываешь блок `über`, ты физически не видишь, что `denken` уже лежит двумя экранами
выше в блоке `an`. Результат: 21 пропущенная связка из 196, то есть больше 10 % датасета.
Хуже того — на этих неполных данных была построена статистика («95 % слов имеют один предлог»),
и она едва не определила выбор интерфейса. **Ошибка сбора выглядела как факт о языке.**

### Решение: авторский формат, ключом которого является слово

Авторский файл — не массив, а объект, ключ которого — лемма:

```jsonc
{
  "denken": {
    "pos": "verb",
    "patterns": [
      { "prep": "an",   "case": "akk",
        "gloss": { "ru": "думать о ком-л. (держать в мыслях)",
                   "en": "to think of sb. (keep in mind)" } },
      { "prep": "über", "case": "akk",
        "gloss": { "ru": "думать о чём-л. (иметь мнение)",
                   "en": "to think about sth. (have an opinion)" } }
    ]
  },
  "bestehen": {
    "pos": "verb",
    "patterns": [
      { "prep": "auf", "case": "dat", "gloss": { "ru": "настаивать на", "en": "to insist on" } },
      { "prep": "aus", "case": "dat", "gloss": { "ru": "состоять из",   "en": "to consist of" } },
      { "prep": "in",  "case": "dat", "gloss": { "ru": "заключаться в", "en": "to lie in" } }
    ]
  }
}
```

Что это даёт:

- Все связки одного слова физически стоят вплотную. Пропуск виден глазом при простом чтении.
- Повторный ключ — не «дубликат где-то в массиве», а невалидный/затирающий JSON, который
  ловится линтером на первой же проверке.
- Порядок файла — алфавитный по слову, а не по предлогу. Группировка по предлогу
  **запрещена**: именно она породила пропуски.

Плоский массив, удобный для поиска и рендера, **собирается из этого сборкой**, а не пишется руками.
Авторский формат и рантайм-формат — разные вещи, и это осознанное решение.

> Открытый вопрос для агента-архитектора: один файл или разбиение по буквам / по частям речи.
> Критерий — не размер файла, а размер diff'а в PR и вероятность конфликта слияния.

## 3. Схема

### 3.1 `Rektion` — связка (рантайм-запись)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | `string` | да | Стабильный идентификатор: `warten-auf-akk`. На него ссылается состояние SRS — **никогда не переиспользуется и не меняется**. |
| `slug` | `{ word: string; prep: string }` | да | Сегменты адреса: `/en/{word}/{prep}/`. Присваивается один раз и **замораживается**; правила и разрешение коллизий — ADR 0002. Не вычисляется на лету: вычисляемый слаг поехал бы при пересортировке файла и молча переадресовал бы чужие ссылки. |
| `pos` | `'verb' \| 'adj' \| 'noun'` | да | Часть речи слова. |
| `lemma` | `string` | да | `warten`, `stolz`, `Angst`. Существительные — с заглавной. |
| `article` | `'der' \| 'die' \| 'das'` | только `noun` | `die Angst`. |
| `reflexive` | `'akk' \| 'dat' \| null` | только `verb` | `sich freuen` (Akk) vs `sich vorstellen` (Dat). Хранится отдельно от леммы, а не как строка `"sich freuen"` — иначе ломается сортировка и поиск (все рефлексивные глаголы слипаются на букву S). **Принадлежит связке, а не слову**: у `sorgen für` возвратности нет, у `sich sorgen um` есть. Тот же довод, что и с падежом — то, чем слово управляет, есть свойство управления, а не слова. |
| `prep` | `string` | да | Ключ из таблицы предлогов. |
| `case` | `'akk' \| 'dat' \| 'gen'` | да | Падеж **этой связки**, не предлога. |
| `gloss` | `{ ru: string; en: string }` | да | Перевод связки целиком, **с указанием управления**: `ru` «ждать кого-л./что-л.», `en` "to wait for sb./sth.". Оба языка обязательны — см. §3.5. |
| `senseNote` | `{ ru: string; en: string } \| null` | нет | Чем эта связка отличается от других связок того же слова. Обязательна, если у слова больше одной связки (см. инварианты). Тоже на обоих языках: именно это пояснение и продаёт приложение, и оставить его на одном языке — значит сделать вторую локаль второсортной. |
| `examples` | `Example[]` | да, ≥1 | См. 3.2. |
| `clause` | `ClauseForm \| null` | нет | См. 3.4. |
| `rank` | `number` | нет | Частотный ранг связки по корпусу. **Основной порядок изучения.** Не требует объяснения пользователю и не зависит от того, знаком ли он с учебными шкалами. |
| `level` | `'A1'…'C1'` | нет | Уровень CEFR — но **только там, где его называет опубликованный источник** (списки IDS VmP покрывают A1/A2, это ~72 связки). Проставлять уровни остальным восьмистам по интуиции — значит выдумывать данные. Полем в интерфейс не выводим. |
| `tags` | `string[]` | нет | `formal`, `umgangssprachlich`, `veraltet`, `regional`, `selten`. Метка `selten` обязательна там, где вариант засвидетельствован, но редок: DWDS фиксирует `bestehen auf` + Akkusativ как редкий, и если это молча выбросить, датасет начнёт учить маленькой неправде. |
| `sources` | `string[]` | нет | Откуда взято/проверено. Нужно для ревизии данных, а не для показа. |

### 3.2 `Example`

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `de` | `string` | да | `Ich warte auf den Bus.` |
| `ru` | `string` | да | `Я жду автобус.` |
| `en` | `string` | да | `I am waiting for the bus.` |
| `blank` | `[number, number]` | нет | Диапазон символов предлога+артикля для режима «вставь пропущенное». |

Пример обязан **содержать саму связку в согласованной форме** — это проверяемый инвариант, не пожелание.

### 3.3 `Preposition` — отдельная таблица

Предлоги живут отдельно, потому что их свойства принадлежат предлогу, а не связке,
и дублировать их в каждой из ~200 записей бессмысленно.

| Поле | Тип | Описание |
|---|---|---|
| `key` | `string` | `auf` |
| `defaultCase` | `'akk' \| 'dat' \| 'gen' \| 'wechsel'` | Поведение **вне** предложного объекта. Показывается как справка, для связок не используется. |
| `da` | `string` | `darauf` |
| `wo` | `string` | `worauf` |
| `ru` | `string` | Базовое значение — для справочной таблицы. |

### 3.4 `ClauseForm` — придаточное вместо существительного

`Ich warte auf den Bus` → `Ich warte darauf, dass der Bus kommt.`

Это отдельный, тяжело дающийся учащимся слой: da-компаунд становится обязательным
коррелятом, а падеж исчезает с поверхности. Модель должна знать, какие конструкции
допускает связка:

```jsonc
"clause": {
  "dass": true,          // Ich warte darauf, dass ...
  "zuInf": true,         // Ich freue mich darauf, dich zu sehen
  "indirect": false      // Ich denke darüber nach, ob ...
}
```

Пока поле `null` — это «не проверено», а не «не бывает». Различие важно: иначе
непроверенные записи навсегда останутся неотличимы от проверенных отрицательных.

### 3.5 Два языка глоссирования — решение и его цена

Интерфейс существует на русском и английском. Важно понимать, что это **не** задача
локализации интерфейса: подписей кнопок в приложении полтора десятка, и их перевод —
работа на полчаса. Дорого стоит другое: перевод — это **данные**, а не интерфейс.
Каждая связка несёт `gloss`, `senseNote` и перевод каждого примера, и всё это
удваивается.

**Почему решаем это сейчас, а не потом.** Стоимость такого перехода растёт линейно
с числом записей: на нуле записей это правка схемы, на восьмистах — восемьсот
ручных переводов. Мы находимся ровно в той точке, когда это бесплатно. Отложить —
единственный способ сделать дорого.

**Хорошая новость про английский.** Английские глоссы приходят почти даром: основной
источник затравки — английский Wiktionary, и глоссы там уже английские
(`docs/research/DATA_SOURCES.md`). Русские глоссы пишутся руками в любом случае.
То есть двуязычность добавляет работу не там, где кажется: EN достаётся вместе
с данными, RU — это и есть ручной труд, который был бы и без второго языка.

**Что остаётся ручным на обоих языках:** `senseNote` (машинный перевод здесь
недопустим — это самое тонкое место датасета) и переводы примеров.

**Инвариант.** Ни одна связка не входит в базу с заполненным одним языком и пустым
другим. Полупереведённая запись хуже отсутствующей: она молча деградирует одну
из двух версий приложения, и заметить это можно только глазами.

**Третий язык не моделируется.** Структура `{ ru, en }` не мешает добавить немецкий
или любой другой, но пока такой задачи нет, обобщать до `Record<string, string>`
незачем — это ровно та абстракция, которая обходится дороже, чем её отсутствие.

## 4. Производные, которые НЕ хранятся

Хранить то, что выводится, — значит завести второй источник правды и рассинхронизировать его.

- **da-/wo-формы** выводятся из предлога один раз на предлог (`auf` → `darauf` / `worauf`),
  а не пишутся в каждой связке. Правило: предлог на гласную получает `dar-`/`wor-`
  (`darauf`, `worüber`), на согласную — `da-`/`wo-` (`damit`, `wovon`).
  Исключения (`ohne`, `außer`, `seit`, `gegenüber` не образуют da-форм) — свойство
  строки в таблице предлогов, а не связки.
- **Список предлогов данного слова** — это `groupBy(lemma)` по массиву связок.
- **Число связок у слова** (бейдж «2 предлога») — счётчик той же группировки.
- **Обратный индекс «предлог → слова»** — тот же массив, сгруппированный иначе.

Единственный источник правды — массив связок. Всё остальное — его проекции,
вычисляемые при сборке или при загрузке.

## 5. Инварианты (проверяются в CI, падение = красный билд)

Датасет пишется руками, значит проверять его должна машина.

| # | Инвариант | Почему |
|---|---|---|
| 1 | `id` уникален | Ключ URL и SRS-состояния. |
| 2 | `(lemma, pos, prep, case)` уникальна | Прямой дубликат. |
| 3 | `(lemma, pos, prep)` встречается дважды **только** с разными `case` и непустыми `senseNote` | Один предлог с двумя падежами у одного слова — редкость; без пояснения это почти наверняка опечатка. |
| 4 | У слова с >1 связкой **у каждой** связки заполнен `senseNote` | Ровно эти слова — суть приложения. Без пояснения контраст `bestehen auf/aus/in` бесполезен. |
| 5 | `prep` есть в таблице предлогов | Опечатка в предлоге иначе создаёт «новый предлог» в интерфейсе. |
| 6 | `examples[].de` содержит `prep` как отдельное слово | Ловит пример, скопированный от соседней связки. |
| 7 | `examples[].de` содержит форму леммы | То же, с учётом спряжения — проверка по основе, с белым списком для сильных глаголов. |
| 8 | Артикль/предлог в примере согласован с `case` | Настоящая проверка падежа: `auf den Bus` при `case: dat` — ошибка. Реализуется таблицей форм артиклей. |
| 9 | Файл отсортирован по `lemma`, группировка по предлогу отсутствует | Формализация раздела 2. |
| 10 | `article` есть тогда и только тогда, когда `pos === 'noun'` | |
| 10b | Схема строгая: неизвестный ключ — ошибка, а не мусор, который молча выбрасывают | Ловушка YAML: незакавыченная запятая внутри `{ }` обрывает значение, и `{ ru: сообщать, рассказывать…, en: … }` разбирается как `ru: "сообщать"` плюс мусорный ключ. Обрезанная строка остаётся непустой, поэтому все прочие проверки её пропускают. Так пострадали 17 записей из первых 85. Глоссы пишутся блочным видом, а не в одну строку. |
| 10a | У `gloss`, `senseNote` и каждого примера заполнены **оба** языка | Полупереведённая запись молча ухудшает одну из двух версий приложения (§3.5). |
| 11 | `reflexive` не задан при `pos !== 'verb'` | |
| 12 | Пара `(slug.word, slug.prep)` уникальна во всём датасете | Коллизия слагов — это страница, молча затирающая другую страницу при сборке (ADR 0002). |
| 13 | `slug` содержит только `[a-z0-9-]` | Умляут или заглавная в пути дают два написания одного адреса. |
| 14 | `slug` существующей записи не изменился относительно git | Единственная по-настоящему необратимая правка в проекте: сервера для редиректов нет. |

Инварианты 6–8 — самые ценные: они ловят ровно тот класс ошибок, который возникает
при копировании соседней записи, а это основной способ писать такой датасет.

## 6. Схема роста

Порядок важен: каждый следующий шаг опирается на предыдущий.

1. **Seed вручную (~200 связок).** Уже есть в прототипе. Покрывает A2–B1.
2. **Инварианты и CI.** До расширения, не после. Иначе ошибки масштабируются вместе с данными.
3. **Сверка с внешним словарём.** Скрипт прогоняет каждое слово по открытому источнику
   и печатает предлоги, которые есть там, но нет у нас. Ручной сбор всегда даёт пропуски —
   вопрос только в том, ловишь ты их сам или ждёшь, пока наткнёшься.
   Конкретные источники и их лицензии — в `docs/research/DATA_SOURCES.md`.
4. **Частотный ранг** на каждой связке из корпуса — он и задаёт порядок изучения
   и позволяет выпускать подмножества «первые 100 / первые 300». Уровни CEFR
   проставляются только там, где их называет опубликованный источник, и в интерфейс
   не выводятся: шкала A1–C1 требует объяснения, а частота — нет.
5. **SRS.** Требует стабильных `id` (см. инвариант 1) — поэтому и введены с самого начала.

## 7. Что осознанно НЕ моделируется в MVP

- Спряжение и склонение — это делает Verbformen.de, дублировать нечего.
- Валентность целиком (Subjekt + Objekte + Ergänzungen). Полная валентностная рамка —
  предмет E-VALBU; здесь берётся только предложный объект, потому что учат именно его.
- Свободные предложные группы (`am Montag`, `in der Schule`) — это не управление.
- Глаголы с двумя предложными объектами (`mit jdm. über etw. sprechen`) — в MVP пишутся
  как две отдельные связки; объединение в одну рамку отложено до подтверждения, что это нужно.
